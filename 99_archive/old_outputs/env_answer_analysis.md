# 环境回答分析

## 已明确

- 应用真实场景是“给父母找伴奏”。
- 父母参加老年活动，需要乐器演奏和合唱伴奏。
- 常见需求是找指定歌曲伴奏，并可能转到 C 调。
- 当前人工流程依赖 YouTube、抖音、下载网站、ffmpeg 和微信。
- 首版视频来源先做抖音。
- 父母希望可以使用，也可以推荐朋友使用。
- 制作过程需要记录，给学 SC 的女儿做参考。
- W 有一台美国 Debian 12 VM，可作为服务器候选。
- 首版最想省掉找视频、下载、提取音频。

## 关键判断

这不是普通手机 App，核心难点在音视频处理链路。

首版不应只是 W 的内部工具，也要考虑父母可用和可展示。

但重处理链路仍更适合放在服务器或本地后台，不建议把抖音下载、ffmpeg、rubberband 全塞进手机端。

## 潜在 MVP

```text
父母/W 输入歌曲需求
-> 系统辅助找抖音伴奏
-> 下载或导入视频
-> 提取音频
-> 可选变调
-> 输出可播放/可分享音频
-> 记录制作过程
```

## 当前未决

- 首版采用手机 Web/PWA + 服务器处理，还是纯服务器 Web 工具。
- 抖音视频获取方式。
- 是否自动识别原调。
- rubberband ffmpeg 部署在 VM 还是本地。
- 微信分享采用下载文件后手动转发，还是生成链接。
- 美国 VM 资源是否足够。
