# Decision Trace: MVP 范围

## 决策

MVP V1 只做：

```text
抖音分享文本
-> 提取链接
-> 下载视频
-> 提取音频
-> 返回 HTTP 音频链接
```

## 背景

W 的父母经常需要伴奏，W 当前手工流程耗时。

## 备选方案

| 方案 | 优点 | 风险 |
|---|---|---|
| 做完整 App：搜索、下载、变调、分享 | 功能完整 | 范围过大，首版风险高 |
| 做 W 内部工具 | 实现快 | 父母不能直接使用，不满足展示需求 |
| 做手机网页 + 服务端处理 | 父母可用，处理能力在服务端 | 需要部署和维护 |

## 最终选择

手机网页 + 服务端处理，首版只处理抖音分享链接和音频提取。

## 原因

这个范围最小，同时打通真实价值闭环。

## 影响

- 原生 App 延后。
- 自动搜索延后。
- 变调延后。
- 优先搭建服务器处理链路。

## 给女儿看的解释

这是 MVP 思维：第一版不是做所有功能，而是做最小但真实有用的闭环。
