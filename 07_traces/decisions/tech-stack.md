# Decision Trace: 技术栈

## 决策

首版采用：

```text
手机 Web/PWA
+ Python FastAPI
+ yt-dlp/等价下载工具
+ ffmpeg
+ Debian 12 VM
```

## 背景

应用需要处理抖音视频下载和音频提取。父母需要简单入口，W 有可用 Debian VM。

## 备选方案

| 方案 | 优点 | 风险 |
|---|---|---|
| 原生 App | 手机体验好 | 开发和音视频处理复杂 |
| 纯前端 Web | 部署简单 | 无法可靠处理下载和 ffmpeg |
| Web + 后端 | 入口简单，处理能力强 | 需要服务端部署 |

## 最终选择

Web + Python 后端 + ffmpeg。

## 原因

下载和音频处理适合在服务器端执行，手机端只负责输入和播放结果。

## 影响

- 需要创建后端工程。
- 需要部署 ffmpeg 和下载工具。
- 需要考虑文件保留、访问链接和 VM 资源。

## 给女儿看的解释

这是架构分工：手机负责交互，服务器负责重活。好的系统会把任务放到最适合的位置。
