# 01 从家庭需求到 MVP

## 真实需求

爷爷奶奶参加老年活动，需要伴奏。以前需要人工找视频、下载、提取音频，再发给他们。

## 第一步：找出真正痛点

痛点不是“做一个 App”，而是：

```text
把抖音伴奏变成可以播放的音频链接。
```

## 第二步：压缩第一版范围

第一版不做：

- 自动搜索。
- 自动选伴奏。
- 变调。
- 原生 App。
- 账号系统。

第一版只做：

```text
粘贴抖音分享文本 -> 提取音频 -> 返回链接
```

## 第三步：选择合适架构

手机网页适合爷爷奶奶使用。

服务器适合下载视频和处理音频。

所以系统拆成：

```text
手机网页：输入和播放
服务器：下载和转换
```

## 第四步：agent 如何参与

人负责真实判断：

- 谁用。
- 什么最重要。
- 哪些先不做。

agent 负责把判断变成结构：

- MVP 文档。
- 技术栈决策。
- 任务板。
- 开发和验证计划。

## 你要学到的点

软件工程不是先写代码，而是先把真实问题变成清楚的系统边界。
