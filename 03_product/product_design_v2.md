## 产品定位

这是一个给父辈使用的智能伴奏工具。

它不只是“从抖音提取音频”，而是帮助用户完成一个更自然的目标：

```text
我想得到一个音频，并把它变成适合演奏/合唱使用的伴奏。
```

## 核心用户视角

父辈打开页面时，只有两种情况：

1. 手里没有音频，只有抖音视频或链接，需要系统帮忙获取音频。
2. 手里已经有音频，需要上传后播放、下载或变调。

因此首页不应围绕技术流程组织，而应围绕“我现在有没有音频”组织。

## Page 1：初始页

目标：

```text
得到一个音频
```

### 入口 A：从抖音提取

适用场景：

- 用户手里没有音频。
- 用户在抖音里看到一个视频。
- 用户复制了抖音分享文本或链接。

页面重点：

- 让用户知道在哪里粘贴。
- 让用户知道怎么粘贴。
- 让用户知道点击后会生成可以播放和下载的音频。

必须能力：

- 粘贴抖音分享文本或链接。
- 明显的“粘贴链接”按钮。
- 明显的“开始生成”按钮。
- 失败时用人话提示。

### 入口 B：上传已有音频

适用场景：

- 用户手里已有伴奏音频。
- 用户希望上传后变调。
- 可能是 W 先帮父辈准备好音频，再让父辈使用页面调整或下载。

建议范围：

- 支持单文件上传。
- 支持 `mp3`、`m4a`、`wav`。
- 文件大小先限制为 `20MB`。
- 上传文件保留 7 天。
- 上传后进入同一个结果页。
- 上传后也可以播放、下载、复制链接和变调。

暂不做：

- 批量上传。
- 在线剪辑。
- 多音轨编辑。
- 歌名搜索。
- 云盘管理。
- 账号系统。

### 首页结构建议

```text
智能伴奏台

选择你现在有什么：

[从抖音提取伴奏]
粘贴抖音分享链接，生成可播放音频

[上传已有音频]
上传 mp3/m4a/wav，之后可以变调和下载
```

首页应默认突出“从抖音提取”，因为这是当前已验证主流程。

上传入口可以作为第二入口，不抢主任务。

## Page 2：结果页

目标：

```text
使用当前音频
```

结果页可能来自两种路径：

- Page 1 从抖音提取完成。
- Page 1 上传音频完成。
- Page 2 自己生成了一个变调版本。

不管来源如何，用户来到结果页时，核心事实都是：

```text
这里已经有一个当前音频。
```

## Page 2.1：当前音频面板

用户目标：

- 播放当前音频。
- 知道当前音频是什么版本。
- 下载当前音频。
- 复制链接发给别人。
- 知道链接有效到哪天。

必须显示：

- 当前版本名称，例如：
  - 原调
  - 升高 1 个半音
  - 降低 2 个半音
- 音频播放器。
- 下载按钮。
- 复制链接按钮。
- 当前音频链接有效期。

有效期规则：

- 有效期应跟当前音频文件走。
- 当前播放/下载哪个版本，就显示哪个版本的有效期。
- 前端短期可用 `audio_variants[*].created_at + 7天` 显示绝对日期。
- 更稳妥的长期方案是后端直接返回每个音频版本的 `expires_at`。

## Page 2.2：变调面板

用户目标：

- 当前音频太高或太低时，生成一个更适合演奏/合唱的版本。

必须能力：

- 选择升高或降低。
- 选择半音数 `1-11`。
- 显示说明：`1 = 半音，2 = 全音`。
- 点击生成新版本。
- 能切回原调或已有版本。

设计原则：

- 变调是高级功能，不应压过播放和下载。
- “当前播放哪个版本”和“我要生成哪个版本”必须分开。
- 已有版本是切换操作，生成新版本是创建操作。

## Page 2 结构建议

```text
[返回首页]

处理好了

[播放器]

当前播放
原调
[原调] [升高 1] [降低 2]

[下载音频] [复制链接]
当前音频链接有效到 2026.05.24

变调
[升高] [降低]
半音    1 = 半音，2 = 全音
[1..11]
[生成这个版本]
[切回原调]
```

## UI 风格方向

W 希望父辈觉得页面先进、酷、有面子，愿意在人前展示。

当前待外部视觉探索：

- W 已让 Gemini 网站生成 UI 风格方案。
- M 后续负责审查 Gemini 输出是否符合父辈可用性，并把可取部分落到现有前端。

建议视觉关键词：

- 智能伴奏台。
- 音乐控制台。
- 舞台灯感。
- 高级音频设备。
- 大字、大按钮、强主次层级。

需要避免：

- 像后台管理系统。
- 像廉价表单工具。
- 字太小。
- 对比度不足。
- 装饰压过操作。
- 复杂导航。
- 难懂英文。

## 下一步待确认

1. 上传音频是否进入下一版。
2. 上传入口是否给父辈直接看到，还是先放在较弱的第二入口。
3. 上传文件大小是否定为 `20MB`。
4. 支持格式是否先定为 `mp3/m4a/wav`。
5. 上传音频是否也保留 7 天。
6. 是否要求后端为每个音频版本返回明确 `expires_at`。
7. Gemini 风格稿是否采用，以及采用哪部分。
