# MVP V1

## 产品一句话

父母在手机网页中粘贴抖音分享文本，系统在服务器上下载视频、提取音频，并返回可播放的 HTTP 音频链接。

## 用户

- 首版用户：W 的父母。
- 后续用户：父母的朋友。
- 维护者：W。

## 入口

- 手机浏览器网页。
- 可添加到手机桌面作为快捷方式。
- 暂不做原生 App。

## 输入

父母从抖音 App 复制分享文本，粘贴到网页。

系统需要从文本中提取抖音短链接。

V1 只保留一个老人端输入入口：粘贴抖音分享文本或可从中提取的抖音链接。

用户不需要手工提取 URL；系统负责从完整分享文本中自动识别抖音链接。

示例：

```text
4.30 复制打开抖音，看看【林子ds的作品】... https://v.douyin.com/VUkeE3kU-o8/ ...
```

## 主流程

```text
粘贴抖音分享文本
-> 提取抖音链接
-> 服务器下载视频
-> ffmpeg 提取音频
-> 生成 HTTP 音频链接
-> 父母打开链接播放
```

## V1 范围

必须做：

- 手机网页提交抖音分享文本。
- 自动提取第一个抖音链接。
- 支持指定抖音分享链接的处理链路，测试1作为 MVP V1 首个真实 E2E 验收样本。
- 服务端下载视频。
- 服务端提取音频。
- 返回 HTTP 音频链接。
- 成功页优先显示音频播放器。
- 成功页提供复制音频链接按钮。
- 音频保留 7 天。
- 音频链接使用公开但不可猜的随机文件名。
- 失败页只向老人展示人话错误，技术细节只保留在后台记录中。
- 记录制作过程，服务 learning trace。

不做：

- 自动搜索抖音。
- 搜索关键词并下载首位视频，测试2放入 backlog。
- 自动选择伴奏。
- 变调到 C 调。
- 账号系统。
- 历史列表。
- 复杂后台管理。
- 原生 App。

## 验收标准

- 手机网页可提交抖音分享文本。
- 系统能识别文本中的第一个抖音链接。
- 服务器能处理一个抖音链接。
- 成功后生成音频文件。
- 页面优先显示可播放的音频播放器，并提供可复制的 HTTP 音频链接。
- 如果当前已有任务在处理，新提交直接提示服务忙，不设置等待队列。
- 处理过程有记录，便于复盘人和 agent 如何协作。

## V1.1 候选

- 支持 ffmpeg rubberband 变调。
- 支持输入歌名后搜索候选视频。
- 支持任务历史。
- 支持更适合老人使用的大字版界面。
