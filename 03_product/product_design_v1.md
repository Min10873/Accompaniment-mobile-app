# Product Design V1

## 产品定位

这是一个给老人使用的伴奏提取工具。

首版目标不是做完整音乐工具，而是把一个具体流程变简单：

```text
从抖音分享文本中提取伴奏音频，并返回可播放链接
```

## 目标用户

### 主要用户

- W 的父亲。
- W 的母亲。

用户特点：

- 年龄偏大。
- 参加老年活动。
- 有乐器演奏、合唱等伴奏需求。
- 可以使用手机。
- 可以从抖音复制分享文本。

### 次要用户

- 父母的朋友。
- 老年活动队伍成员。

### 维护者

- W。

W 负责：

- 系统建设。
- 异常处理。
- 后续功能迭代。

## 用户目标

老人想要：

- 快速得到某个抖音视频里的伴奏音频。
- 打开链接即可播放。
- 不理解下载、ffmpeg、格式转换等技术细节。

W 想要：

- 减少手工找视频、下载、提取音频的重复劳动。
- 让父母能自己完成第一步。
- 保留制作过程，给女儿学习人和 agent 如何协作。

## V1 用户故事

### 故事 1：父母提交抖音分享文本

作为父母，我从抖音复制一个视频分享文本，粘贴到网页里，点击按钮后，系统帮我处理。

验收：

- 页面有明确输入框。
- 页面说明可以粘贴抖音分享文本。
- 提交后能看到处理状态。

### 故事 2：父母获得音频链接

作为父母，我希望处理完成后看到一个可以点击的音频链接。

验收：

- 成功后显示音频链接。
- 链接可直接打开播放。
- 页面文字简单，不出现技术术语。

### 故事 3：W 处理异常

作为 W，我希望失败时能知道失败原因，方便排查。

验收：

- 未识别到链接时提示清楚。
- 下载失败时提示清楚。
- 提取失败时提示清楚。
- 后台保留任务记录。

### 故事 4：女儿学习过程

作为女儿，我希望看到这个产品是如何由真实需求一步步变成软件的。

验收：

- 关键阶段有 learning trace。
- 重要决策有原因说明。
- 记录体现人和 agent 的协作分工。

## V1 页面设计原则

- 大字。
- 大按钮。
- 单任务。
- 单入口，只粘贴抖音分享文本或可识别的抖音链接。
- 少解释。
- 少选项。
- 错误提示要像人话。
- 成功结果要突出。

## V1 页面结构

```text
标题：伴奏提取

说明：粘贴抖音分享文本，系统会提取音频

输入区：
  多行文本框

主按钮：
  开始提取

状态区：
  等待提交 / 正在处理 / 处理完成 / 处理失败

结果区：
  音频播放链接
```

## V1 页面状态

V1 使用手机端单页状态切换，不做复杂导航。

### 初始输入

- 标题：伴奏提取
- 说明：粘贴抖音分享文本，提取可以播放的音频。
- 输入框占位：请粘贴抖音分享文本
- 辅助提示：从抖音点分享，再复制链接或分享文字。
- 主按钮：开始提取
- 按钮状态：没有输入时置灰，不可点击。

### 输入后可提交

- 输入框显示用户粘贴内容。
- 主按钮：开始提取
- 次按钮：清空内容
- 如果前端能初步识别抖音链接，可提示：已看到抖音链接，可以开始提取。
- 如果前端不做实时识别，输入后启用按钮即可。

### 处理中

- 状态标题：正在处理
- 状态说明：正在处理，请稍等。
- 辅助说明：一般需要几十秒。
- 主按钮：正在提取...
- 按钮状态：置灰，不可点击。
- 输入框只读或禁用，防止处理中修改输入。
- V1 不提供取消按钮。

### 成功

- 状态标题：处理好了
- 状态说明：点击下面可以播放音频。
- 成功页必须显示可直接播放的音频控件。
- 默认不显示完整音频链接，避免长链接占屏。
- 主操作：播放音频。
- 次按钮：复制音频链接
- 次按钮：再提取一个
- 保留提示：链接会保留 7 天。
- 复制成功反馈：已复制，可以发给别人。
- 如果复制失败，提示：没有复制成功，请长按链接复制。
- 复制失败时再显示完整链接，作为兜底。

### 失败

- 通用失败标题：没有处理成功
- 通用失败说明：这次没有处理成功，请换一个视频试试。
- 主按钮：重新粘贴
- 次按钮：再试一次
- 不向老人展示技术错误。
- 失败页可以显示小号任务号，例如：给家人排查：任务号 ABC123。

### 未识别链接

- 状态标题：没有找到抖音链接
- 状态说明：请重新复制分享文本。
- 主按钮：重新粘贴
- 辅助提示：从抖音分享里复制带链接的文字。
- 次按钮：无。

## V1 视觉和可用性

- 页面按手机宽度优先设计。
- 内容左右边距建议 20px。
- 内容最大宽度建议 430px，居中。
- 页面背景使用 `#F7F8FA`。
- 主文字使用 `#111827`。
- 次文字使用 `#4B5563`。
- 弱提示文字使用 `#6B7280`。
- 卡片/输入背景使用 `#FFFFFF`。
- 边框使用 `#D1D5DB`。
- 页面标题建议 28px，粗体。
- 说明文字建议 18px。
- 输入框文字建议 18px。
- 主按钮文字建议 22px，粗体。
- 状态提示建议 20px。
- 辅助说明建议 16px。
- 主按钮高度建议 56-64px。
- 次按钮高度建议 48-52px。
- 输入框高度建议 160-200px。
- 组件间距建议 16-24px。
- 输入框圆角 8px，内边距 16px。
- 主按钮圆角 8px。
- 次按钮圆角 8px。
- 状态提示框圆角 8px，内边距 16px。
- 主按钮使用蓝色 `#2563EB`。
- 主按钮按下态使用 `#1D4ED8`。
- 禁用按钮背景使用 `#D1D5DB`，文字使用 `#6B7280`。
- 成功状态使用绿色 `#16A34A`，成功浅底使用 `#ECFDF3`。
- 失败状态使用橙红色 `#DC2626`，失败浅底使用 `#FEF2F2`，文案保持温和。
- 颜色不能作为唯一状态提示，状态必须同时有文字。
- 所有可点击区域建议至少 48px 高。
- V1 名称暂用“伴奏提取”。
- V1 不加入额外亲切称呼文案，保持工具页清楚直接。

## V1 UI Mock 基准

后续 UI mock 和 Playwright 截图以以下状态为基准：

| 状态 | 关键要求 |
|---|---|
| `idle` | 空输入框，按钮禁用，无次按钮 |
| `filled` | 输入框显示示例分享文本，按钮可点击，可清空内容 |
| `processing` | 输入框只读，显示正在处理，不提供取消按钮 |
| `success` | 优先显示播放器，显示复制音频链接、再提取一个、7 天保留提示 |
| `error` | 显示通用失败文案、重新粘贴、再试一次、小号任务号 |
| `no-link` | 显示未识别链接文案，只引导重新粘贴，不显示任务号 |

不能因为后续实现而改变：

- 仍然是手机端单页，不加多页面导航。
- 首屏主入口仍然是粘贴抖音分享文本。
- 主按钮必须蓝色且足够大。
- 成功页必须优先显示播放器，不默认展示完整长链接。
- 失败页不得暴露技术错误。
- 处理中不得提供取消按钮。
- 不加入登录、搜索、变调、历史列表。
- 未识别链接和通用处理失败要分开展示。

## V1 不做

- 不做登录。
- 不做用户管理。
- 不做搜索。
- 不做关键词搜索后下载首位视频，该能力放入 backlog。
- 不做自动选伴奏。
- 不做变调。
- 不做复杂历史列表。
- 不做原生 App。

## V1 成功标准

产品层面成功：

- 父母知道该粘贴什么。
- 父母知道该点哪个按钮。
- 父母能看到处理状态。
- 父母能点击音频链接播放。
- 失败时父母不会被技术错误吓住。

W 层面成功：

- W 少做下载和提取音频的重复劳动。
- W 能排查失败任务。
- W 能继续迭代。

女儿层面成功：

- 能通过 trace 看懂需求如何变成产品设计。
